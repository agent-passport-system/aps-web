Memo · aps/01 · the shift On the new shape of authority.

Agent Passport System gives every AI agent a verifiable identity, ties it to the person or company it represents, and enforces the scope, budget, and conditions of its authority.

Every permitted action gets a signed receipt. Every denied action leaves evidence. The result is a cryptographic trail of who authorized the agent, what it was allowed to do, and what actually happened.

Today

Agents act anonymously. No audit trail. Revocation means shutting everything down.

With Agent Passport System

Every agent carries a signed identity. Authority can only narrow. Full cryptographic audit trail.

05Payments

Agents pay through your rails, with their proofs.

A payment is an action. Every charge clears the same four gates — identity, scope, budget, policy — and emits a signed receipt. APS doesn't move money. It gates which rail moves it, under what authority, with what evidence.

08Questions

What people actually ask.

Nine questions, plain answers. For the long version, read the spec.
Q.01What does the protocol do?+
Agent Passport System makes every AI agent accountable. Every agent gets a cryptographic identity (Ed25519). Authority can only narrow, never expand. Trust is earned through performance, not granted. One API call revokes all downstream access. Cryptographic proof of every action, every dollar, every decision.
Q.02How is it different from other agent frameworks?+
Most frameworks handle orchestration. APS handles enforcement — what can this agent do, and what happens when it violates a constraint? Bring your own identity (did:key, did:web, SPIFFE, OAuth). The gateway is both judge and executor. Monotonic narrowing, cascade revocation, signed receipts, governance terms that travel with the artifact, agent-to-agent payments, Merkle-anchored attribution. Verifier hot path p50 318ns (Mac M3). 2,966 conformance tests. Works alongside any orchestration framework.
Q.03Is this production-ready?+
Verifier hot path p50 318ns (Mac M3) / 347ns (AWS c7i.2xlarge) / 420ns (bare-metal EPYC 7313P). 2,966 conformance tests. Eight papers on Zenodo. IETF Internet-Draft (draft-pidlisnyi-aps-01). SDK on npm and PyPI under agent-passport-system. MCP server exposes the full protocol surface. Tens of thousands of installs. Apache 2.0.
Q.04Who is this for?+
Anyone deploying AI agents that act on behalf of people or companies. Enterprises that need audit trails and spending controls. Developers building multi-agent systems. Platforms that need to verify which agents can do what.
Q.05How does delegation work?+
A human delegates authority to an agent with explicit scope: what tools, how much money, which services. The agent can sub-delegate, but authority can only narrow, never expand. Revoke the root and everything downstream dies instantly.
Q.06How do I integrate with my existing framework?+
APS works alongside any agent framework — CrewAI, LangChain, A2A, ADK, or custom. The SDK provides the identity and governance layer; your framework handles orchestration. The MCP server exposes every protocol operation. Install the SDK, issue a passport, attach it to your agent. The framework doesn't need to change.
Q.07How does revocation work at scale?+
Cascade revocation. Delegation chains form a tree. Revoke any node and every downstream delegation dies instantly — all sub-agents, all sub-sub-agents. One API call. The gateway enforces this at the boundary, so revoked agents can't sneak through on cached credentials. Circuit breakers auto-trip on error-rate spikes.
Q.08Is there a standard?+
Yes. draft-pidlisnyi-aps-01 is submitted to the IETF as an Internet-Draft. Eight papers on Zenodo formalize the theory: monotonic narrowing, product-lattice authority, institutional governance composition, receipt admissibility. The conformance suite is the contract for interoperability.
Q.09What about compliance?+
Every permitted action emits a signed receipt. Every denied action leaves evidence. The audit trail is cryptographic, not log-based — receipts are independently verifiable from inclusion proofs, no need to trust the log operator. Compliance posture can be reconstructed from the receipt chain alone. AIVSS-style risk assessment ships in the SDK.
