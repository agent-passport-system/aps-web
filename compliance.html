Compliance Mapping

Compliance evidence for AI agents

Enterprise teams evaluating AI agents need evidence of authorization, policy enforcement and recorded decisions. This page maps what an auditor asks to the signed records APS produces, and says what each record does not show.

What this page is and is not. The Agent Passport System (APS) does not make a system compliant and does not certify anything. Compliance belongs to the organization and its auditors. APS produces signed records that an organization can use as evidence. Whether a rule applies to a given system is a legal question for that organization. Nothing here is legal advice.

What an auditor asks, and what APS produces

Who is this agent, and who answers for it?

An agent passport is a self-signed identity record for one agent. A separately signed principal binding names the person or organization the agent acts for.

What was the agent allowed to do?

A delegation chain records the scope, the spending limit and the time window the agent received. Authority can only narrow each time it is passed on. A verifier rejects a chain in which a sub-agent holds more than its parent.

Was the action checked before it ran?

The gateway checks the agent's delegated authority before the action runs and signs its decision, whether it permits or refuses.

What did the agent do, and can the record be changed afterwards?

Each decision produces a signed receipt. Changing a receipt after the fact breaks its signature, and anyone can check that with the published verifier or in the browser inspector.

Can a person stop it?

Revoking a delegation also revokes every delegation derived from it, and the revocation is itself a signed record. Once the gateway has the revocation, its next check refuses the agent.

What data did the agent use?

Data access receipts record which data an agent accessed, under whose authority and for which declared purpose, and what it was refused. See data usage evidence.

Can an outside party verify this without trusting the vendor?

The record formats, the specification and the test vectors are public under Apache 2.0. Verification runs offline with open source code.

What the records do not show

A signed record has limits. For each question above, this is what the record does not show.

  • Who is this agent, and who answers for it? That the named principal is a verified legal entity. The deployment has to check that itself.
  • What was the agent allowed to do? Whether the grant itself was a good decision. That is the organization's policy.
  • Was the action checked before it ran? Anything about actions that never pass through the gateway. A decision is enforced only where the gateway sits in the path of the action.
  • What did the agent do, and can the record be changed afterwards? That the outside effect happened. A receipt records the request and the decision. Evidence of the real outcome comes from the system that carried out the action.
  • Can a person stop it? The quality of human review, an action that already ran before the revocation, or a gateway that has not yet received it.
  • What data did the agent use? What a model did with the data internally.
  • Can an outside party verify this without trusting the vendor? Who operated the gateway honestly. The signature shows which key signed, and the organization has to protect that key.

What stays with the team that deploys it

A valid signature shows that a record was not changed. It does not show that the set of records is complete. These points decide how much the records are worth as evidence.

ResponsibilityWhy it matters
Every action goes through the gatewayAn action that bypasses the gateway is neither checked nor recorded.
Revocations reach the gateway quicklyThe gateway can only refuse on a revocation it has received.
Signing keys are protected and the trusted keys are knownA verifier trusts a record only as far as it trusts the key that signed it.
Records are stored completely and kept as long as requiredRetention periods and storage are the organization's own, and APS does not set them.

Who uses these records

Security teams set and withdraw what each agent may do. Risk and compliance teams collect the signed records as evidence. Internal audit verifies them with open source code, without access to the system that produced them. Platform engineers add APS on top of the identity an agent already has: it accepts did:key, did:web, SPIFFE SVID and OAuth identities, and it binds to Model Context Protocol tool calls.

Status

APS is an open protocol with reference implementations under Apache 2.0. APS holds no certification under any framework on this page and has had no formal security audit by a third party. The mapping above is the author's reading and is open to correction.

What APS is

AI agents act for people and companies, but the systems around them often cannot show who authorized an action and what the agent was allowed to do.

The Agent Passport System is an Apache 2.0 open protocol that gives an agent a verifiable identity, ties it to the person or company it acts for, and checks the scope, budget and conditions of its authority before it acts.

Every action that goes through the gateway gets a signed decision, whether it is permitted or denied.

A receipt shows what was decided and under whose permission. It does not by itself show that the action succeeded outside the gateway.
