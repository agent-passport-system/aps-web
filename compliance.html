Compliance

Cryptographic audit trail for AI agents. Maps to EU AI Act Articles 14 and 26, NIST AI RMF, ISO 42001.

Who this is for

Regulated industries running agents (financial services, healthcare, defense, government), EU operators of any sector, and any company whose Chief Compliance Officer needs to answer "show me the audit trail" with cryptographic evidence rather than text logs.

Most agent stacks log to Kibana or Datadog. Those logs are evidentiary, but they carry no chain of authority, no signed scope, no contestability surface, and no proof of which inputs the agent actually saw at decision time. When a regulator asks for the audit trail, you hand them log lines and hope.

What we ship

Action receipts

Every agent action signs a receipt: who acted, under which delegation, with which scope, against which target, at which time. Ed25519 over RFC 8785 JCS canonical form.

Authority-boundary receipts

When an action approaches the limit of delegated authority, the gateway emits a signed authority-boundary receipt. Proves the agent operated inside scope, even at the edge.

Custody receipts

For evidence that needs chain of custody (medical records, regulated documents, financial artifacts), custody receipts track who held what, when, and under whose authority.

Contestability receipts

The dispute lifecycle, signed end-to-end. A subject can contest an automated decision; the receipt chain captures the dispute, the review, and the resolution. Aligns with EU AI Act Article 86 right to explanation.

Instruction Provenance

Binds agent authority to the digest of the instruction file (system prompt, tools list, persona) at delegation time. If the instructions drift between turns, the action denies. Drift denial across turns.

APSBundle Merkle aggregation

Action, access, derivation, custody, and contestability receipts aggregate into one signed Merkle root per session or period. Audit pulls one root, verifies in O(log n) per receipt.

Claim-evidence type registry

Cryptographic validity is not evidentiary sufficiency. The registry separates procedural validity from effect safety: a valid receipt proves what it claims, no more. Receipt laundering becomes structurally hard.

Cognitive attestation

For high-stakes decisions, the agent signs an interpretable decomposition of latent state at decision time. Optional, opt-in, but available when compliance needs go past behavioral logs.

How it looks in code

Below is the audit query path: pull a session's bundle, verify the Merkle root, list every action with its scope and outcome.

// Audit query: replay everything an agent did in Q2 against patient record system

import {
  loadAPSBundle,
  verifyBundleRoot,
  filterReceipts,
} from 'agent-passport-system/v2/accountability'

const bundle = await loadAPSBundle({
  agentId: 'agent:radiology-assistant',
  period: { from: '2026-04-01', to: '2026-06-30' },
})

// 1. Verify the Merkle root: one signature, O(log n) per-receipt proofs
const rootValid = verifyBundleRoot(bundle)
if (!rootValid) throw new Error('Bundle root signature invalid')

// 2. Filter to actions touching patient record 8421
const touched = filterReceipts(bundle, {
  claim_type: 'aps.action.v1',
  target: { contains: 'patient:8421' },
})

// 3. For each, the receipt carries: signer_did, scope_of_claim, timestamp,
//    delegation_ref (the authority chain), and any contestability records.
return touched

What audit receipts do not prove

A signed audit bundle proves procedural validity: every action had a delegation, a scope, a signer, a timestamp, and a canonical signature chain. The bundle does not prove:

  • The decisions were correct, fair, or unbiased (procedural validity is not effect safety; see Paper 8: The Evidence-Safety Gap)
  • The agent's behavior matched its stated intent (intent is signed, behavior is observed)
  • The delegation was authorized by the right human (delegation chain anchors at the principal; verifying the principal is your IAM problem)
  • Compliance with any specific regulation (your counsel determines sufficiency)
