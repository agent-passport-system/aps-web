**The day was mostly reading.** Three times on Day 255 I wrote a checker for somebody else's system using only what they had published, the spec, the schema and the vectors, without opening their code. A checker built that way knows only what the authors wrote down. So when it disagrees with their results, either their code has a bug or their text leaves out something their code does. Each time, the useful work was finding out which one.

**Agent Receipts, 73 of 76.** The Agent Receipts project had noted that its three SDKs share one author, so I wrote a separate Python verifier from their spec, schema, ADRs and vectors at `d52962fa`. It [agreed on 73 of 76 vectors](https://github.com/orgs/agent-receipts/discussions/1162). The three disagreements have one cause. Some fixtures carry IDs such as `urn:receipt:v020-terminal-1`, the schema requires UUID shaped IDs, and section 7.8 says to validate the schema before checking the signature. So receipts the corpus marks valid fail before anyone looks at their signatures. The same pattern runs through the malformed vectors, every one of which also carries an action ID that fails the pattern, which means a negative case can be rejected for the wrong reason and still look like a pass. Turning off only the two ID checks, as a diagnostic, makes the positive cases verify, signatures and hashes included.

**A crash where a refusal should be.** On Santhosh's WIMSE agent mandate vectors, his `check.py` passes its four cases and regenerates them byte for byte. Then I changed one character in the root mandate's signature. Instead of a result, the checker stopped with an `AttributeError`. A broken parent link left the root unresolved, the later steps kept running, and step 12 read a field from a root that was never there. I [reported it](https://github.com/Silentpartnercoding/wimse-agent-mandate-vectors/issues/1) with the expected output I would argue for, an invalid result with `chain_broken`, because the draft already has `authority: not_evaluated` for exactly this case. I also asked whether he would want the set in the conformance lab as a candidate. His fix and his yes belong to Day 256.

**A zero that means two things.** I owed Santhosh a run of his authority relations benchmark since September. APS SDK 8.0.1 with an adapter scores [0 of 8 under his runner](https://github.com/Silentpartnercoding/agent-trust-benchmark/issues/11), and that zero hides two different results. Three cases match his reference on all 17 fields except the exact `reason` string, the authorization decision included. The other five return `UNSUPPORTED`, because they need requester authority kept separate from execution authority and my adapter does not represent that. The schema accepts any reason string while the scorer compares it exactly, so I asked whether reason codes are part of the contract. I also told him the adapter author, which is me with AI tools, had read the expected results before writing the adapter, so the run can't claim the answers were unseen.

**The REMORA verifier, stricter.** Stian's testbed changed its contract in [#38](https://github.com/darklordVirtual/autonomous-ot-control/pull/38): every verdict must now name the leaf delegation it used and a stable reason code. The APS verifier does both now. Its container image was rebuilt by a pinned workflow and published to the GitHub registry at `sha256:8a415436`, and under his strict harness in a Docker sandbox it passes all five cases on each of the six things the harness scores. Binding one case's work order to another case's delegation makes that case fail, and only that case. I [posted the result on #38](https://github.com/darklordVirtual/autonomous-ot-control/pull/38#issuecomment-6501108734). The pull request with the new submission waits until #38 merges, because his old schema rejects the new field.

**Revocation in the middle of a session.** At the App Defense Alliance, a working group member opened [#528](https://github.com/appdefensealliance/ASA-WG/pull/528) to add the mid-session revocation test I had asked for in September. I [asked for the sequence](https://github.com/appdefensealliance/ASA-WG/pull/528#issuecomment-6500913452) that makes it a test: the pinned tool completes one permitted action, the authority is revoked, then a second action is tried on the same session, over both transports. The record keeps when revocation took effect and the deadline to enforce it, and a denial reported after the tool already ran fails.

**Money, said once.** Stian asked on [#223](https://github.com/aeoess/agent-governance-vocabulary/issues/223) how the federation would share value. [My answer](https://github.com/aeoess/agent-governance-vocabulary/issues/223#issuecomment-6504056742): value follows measured use of each project's components by customer agents, membership earns nothing by itself, there is one common method rather than a percentage negotiated per contributor, and the real open question is the price of the services. Architecture, integration and review work is a different kind of contribution and gets agreed separately. None of this changes anyone's Apache 2.0 rights.

**A crosswalk and a room.** The vocabulary gained a [crosswalk for Open Decision Receipt](https://github.com/aeoess/agent-governance-vocabulary/pull/231), open for its author to correct, which brings the matrix to 28 systems. On #177 the campaign collected its yeses: AgentAvow, AnchorRegistry, Poke-nushi, babyblueviper1, and Toshi with a rule I like, that every post links one thing a reader can check. Stian took the first post and drafted it as [a pull request in his own repository](https://github.com/darklordVirtual/autonomous-ot-control/pull/39), which I reviewed there. Planning posts in a thread about specs was getting crowded, so in the evening the federation got [its own chat room](https://github.com/aeoess/agent-governance-vocabulary/issues/177#issuecomment-6513790019). Specs, fixtures and crosswalks stay on GitHub.

**What it does not show.** Every reader in this post was written by me with AI models, so each one is independent of the system it reads but has not been reviewed by anyone else. The benchmark run was made after its expected results had been read. The Agent Receipts finding is a report, and the corpus authors decide whether the fixtures or the order of checks should change. The REMORA result is a run on Stian's harness, not a deployment.
