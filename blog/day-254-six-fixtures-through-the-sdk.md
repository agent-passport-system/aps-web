**Six robot safety fixtures through the SDK.** I had told Pashkov on #177 that I would run SINT's runtime safety fixtures against APS, so I [ran all six](https://github.com/aeoess/agent-governance-vocabulary/issues/177#issuecomment-6485573568) through a local harness on the TypeScript SDK 8.0.1, with the fixture file pinned at `d712598`. Each SINT token became an `AuthorityDelegationV1` grant and each fixture action became a decision. One fixture matched the expected verdict outright, three matched in part, and two could not be evaluated. The gaps are APS findings, not SINT's. A numeric bound such as a maximum velocity has no place in the seven facets of an authority vector, so a grant can say which topics an agent may publish to but not how fast it may drive. An authority-only check passes an emergency stop case that should refuse. SINT's `escalate` and `rollback` verdicts sit outside `permit`, `deny` and `narrow`. Its `action_ref` carries a `sha256:` prefix and allows a null `delegation_ref`, APS does neither. The numeric bound is a question for draft-05, and it gets its own thread rather than a line in a reply.

**A reader that matches 31 of 31, and the adapter it will feed.** Tetsuro's anchor pointer draft 1.2 added three vectors, and our reader, written from the draft text without reading his code, now passes [31 of 31 on `53e44de`](https://github.com/aeoess/agent-governance-vocabulary/issues/217#issuecomment-6475609825) while still matching the 28 expectations of draft 1.1. Removing any one of the three new checks makes its vector fail, which is what the checks are for. In the refund sandbox, Toshi published his `aps-receipt` adapter at `12a48bbe`, and I [checked it](https://github.com/aeoess/agent-governance-vocabulary/issues/193#issuecomment-6475610388): the pins match the npm integrity string and the 8.0.1 tag, the selftest passes its 70 checks, and calling `verifyReceiptWithDecisionV1` directly agrees with the adapter on the positive case and both negatives. One ordering note went back, a decision that is both expired and revoked reports expired, because the adapter reads `valid_until` first. Fabio's PIC adapter merged on his side the same day. The door that consumes a decision once is not built, and Toshi declined to name a run date before it exists, which is the right order.

**APS inside the REMORA sandbox.** Stian's testbed harness refuses an edge that is not sandboxed, so the APS verifier now ships as a container image with the SDK bundled inside, and the harness runs it with the same five of five verdicts as the unbundled run. He merged it as [#35](https://github.com/darklordVirtual/autonomous-ot-control/pull/35). The offline fixtures stay apart from the runtime work orders, as [agreed on #27](https://github.com/darklordVirtual/autonomous-ot-control/issues/27#issuecomment-6475642387).

**Lab and vocabulary merges.** In the lab, Andrey's TPM bound key family merged as a candidate after four corrections to its claims, the argument designated resources family merged as a candidate with no independent run yet, and a CRLF hygiene check learned to skip binary files. In the vocabulary, SINT and Veritas Acta opted in to shared decisions, which makes eight projects. The boundary map window closed without PIC's and Nobulex's confirmations, so under its own rule the map stays open until they arrive, and I [said so on #209](https://github.com/aeoess/agent-governance-vocabulary/pull/209#issuecomment-6485736330). Stian opened [#223](https://github.com/aeoess/agent-governance-vocabulary/issues/223) on commercial use and contributor rights. I answer there tomorrow.

**A proposal about attention.** I [proposed on #177](https://github.com/aeoess/agent-governance-vocabulary/issues/177#issuecomment-6486662304) that the projects on the map run a social media campaign together: the project the current work runs on writes the post, the rest of us tag each other and share it in our own words, and anyone can stay out. Most of the work I see in this field is theoretical. This group does the practical work, and I'd like it to be seen.

**The documentation site, and what it found.** APS now has a documentation site at [agent-passport.org/docs](https://agent-passport.org/docs/), built as static pages from the text that already existed, with the old single page redirecting into it. An audit of those twelve pages against the released packages found 33 problems, seven of them urgent. The published quickstart recommended two functions that throw a migration error in 8.0.1. It called an agent trustworthy on a result where issuer trust was never checked. One sample used `eval` as a variable name, which is a syntax error in a module. The Python README quickstart failed at its first step. The repair replaced the quickstart with a governed action example that runs under `npm test` against the pinned package, with every output on the page pasted from the run, and added reference pages for identity, authority, signed bytes and receipt verification. The site also gained a strip above the footer naming where the work happens: the Individual Internet-Draft, the W3C AI Agent Protocol community group, the OWASP Agentic Skills Top 10, CoSAI Workstream 4 and the conformance lab at LF Decentralized Trust.

**What it does not show.** The SINT run maps fixtures onto APS grants, it does not run SINT's own gateway. Toshi's adapter covers the admission checks, not the door, so the refund sandbox still has no connected run. The reader result on #217 is author-produced. The documentation audit and its repairs were both done with AI models under my direction, so neither counts as an outside review. No project has answered the campaign proposal yet.
