# Day 225: a conformance test that passed without the thing it tested, and eleven people writing down how their projects connect

**A test that could not fail.** The Universal Commerce Protocol conformance suite has a test for AP2 mandates. It sent a placeholder mandate and expected the checkout to complete. The mock platform profile never declared AP2, so AP2 was never negotiated, and a business that ignores mandates passed. I opened [#114](https://github.com/Universal-Commerce-Protocol/conformance/issues/114) and then [PR #115](https://github.com/Universal-Commerce-Protocol/conformance/pull/115). Getting there took several rounds, and every round my own patch was wrong in a new way. The first version tested against a local server that shared its blind spot. The second used the capability name from a newer release than the one the suite runs, because AP2's names changed between the 2026-04-08 and 2026-08-25 releases. The PR now runs the AP2 tests only when AP2 is in the negotiated capability intersection, adds the missing negative case, and skips the old positive test. A server that actually verifies mandates has to reject that placeholder, so the positive case needs a real signed mandate fixture, and nobody has one yet.

**Writing down how projects connect.** The federation thread ([#177](https://github.com/aeoess/agent-governance-vocabulary/issues/177)) grew to eleven people. The ten principles went into [PR #178](https://github.com/aeoess/agent-governance-vocabulary/pull/178), and a [boundary map](https://github.com/aeoess/agent-governance-vocabulary/pull/179) went into #179. The map is a graph, not a stack. Each project is its own node, and each line says what crosses it and how far it has actually been tested. kenneives' AgentAvow fixture ran unchanged through an APS-side consumer, 30 of 30. It also showed two places where the projects do not map onto each other. His attestation names a repository or server, while APS authorizes a specific tool. And his manifest digest covers every definition file the scan saw, while an APS metadata pin covers one tool. Both are recorded as boundaries, not failures. In the same spirit I corrected our own [crosswalk with argentum-core](https://github.com/aeoess/agent-governance-vocabulary/pull/180). It had said since May that the two `action_ref` digests could not be joined byte for byte. That stopped being true when argentum moved to JCS. The two now agree on inputs both accept, and still differ on non-ASCII values and empty scope.

**A boundary before the effect.** After the runtime we tried last week did not expose a point below the tool call, I looked at two more runtimes and one governance toolkit. NVIDIA's OpenShell lets an external middleware refuse an outbound HTTP request before the relay writes it upstream. I started a reference middleware on that boundary for one case: deny when an ancestor delegation has been revoked. The first gate was 25 allowed requests reaching upstream and 25 denied requests with zero bytes reaching upstream, through OpenShell's real relay code. It passed that night. This is our code on their extension point. It is not an OpenShell integration, and nothing has been sent to NVIDIA.

**Smaller things.** Two lifecycle issues for the x402 identity working group, on [delegation at depth](https://github.com/x402-foundation/wg-identity/issues/24) and [key rotation](https://github.com/x402-foundation/wg-identity/issues/32). A review of the evidence sufficiency cases for CoSAI's RFC-189, which ended with astrogilda and me agreeing to co-lead those conformance cases. And the APS to PriorSeal payment pair went into the lab as [record #139](https://github.com/Agent-Authority-Conformance/aps-conformance-suite/pull/139), where imokokok's own run of our verifier became a separate candidate record for one of its six claims. Three of the claims still have no independent record.
