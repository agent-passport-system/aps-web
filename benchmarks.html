Speed, layer by layer

Median on bare metal Linux. The tick marks p99.

APS is measured at four layers, from the bare verifier to a full trip through the gateway, on three machines: bare metal Linux on an AMD EPYC 7313P as the reference, AWS c7i on Intel Xeon 8488C, and an Apple M3. The core layers run single threaded over 1,000,000 iterations, the round trip over 1,000. The scale is logarithmic, because the slowest layer is about 2,000 times the fastest.

  1. L0Verifier core420 ns

    Signature and delegation chain check in the Rust reference verifier, warm cache. p99 470 ns. Apple M3 292 ns, AWS c7i 347 ns.

  2. L2SDK call6.5 µs

    The same check called from TypeScript through the native binding. p99 8.1 µs. Apple M3 3.9 µs, AWS c7i 5.7 µs.

  3. L3Durable record7.6 µs

    The call plus an audit record written to disk through a queued commit. p99 13.2 µs. Apple M3 4.0 µs, AWS c7i 6.7 µs.

  4. L4Gateway round trip822 µs

    A full authorization request across the enforcement boundary and back. p99 6.01 ms. Apple M3 305 µs, AWS c7i 1.07 ms.

The deny path of the verifier matches L0 within noise, so a refusal costs no more than an approval. Writing each record with its own fsync instead of a queued commit is bound by the disk: about 1.3 ms on server NVMe and 4 ms on the Mac. Calling through the TypeScript binding costs about 13 to 16 times the bare Rust check on all three machines. Results and the captured environment of each machine are in benchmarks/prototype-1/results.

The public harness, rerun

SDK 8.0.1, 2026-10-31

A second suite runs the whole authorization path in TypeScript in one process: signature, scope, reputation, clock and every constraint. It uses a public test gateway, not the hosted one, so anyone can run it with npx tsx tests/benchmark-gateway.ts. Three runs, 500 calls per scenario. The figures below are the slowest median and the lowest throughput of the three, never the best run.

Scenariop50p99
Signature and scope only0.38 ms0.45 ms
Every constraint0.37 ms0.95 ms
Refused, spend exceeded0.31 ms0.39 ms
100 calls back to back2,600 calls per second, one process

Measured on an Apple M3 laptop, which is a developer machine and not one of the three reference machines. Checking every constraint costs no more than checking the signature and scope alone, so the constraints are not where the time goes. The same harness on SDK 4.4.0 in August measured 0.14 ms on the same machine, and rerun tonight on that version it still does. 8.0.1 is slower on this path, and I have not yet profiled why.

What the gateway checks

15 kinds of constraint

Every action is checked against each constraint that applies, and the gateway stops at the first one that fails. Authority itself travels as seven facets (scope, spend, depth, time, reputation, values and reversibility), and each can only narrow as it is delegated.

  • 01Timeapproval TTL and delegation expiry
  • 02Spendper action and cumulative limits
  • 03Scopetool, parameters and target
  • 04Reputationtier threshold and evidence count
  • 05Valuesvalues floor, graduated
  • 06Revocationrevoked delegation and its cascade
  • 07Reversibilitytentative, compensable or irreversible
  • 08Governanceartifact version, stale attestation
  • 09Identitypassport and signature
  • 10Replayrequest ID reuse
  • 11Cross chaintaint and confused deputy
  • 12Audienceproof bound to one recipient
  • 13Escalationbounded escalation grants
  • 14Fidelityagent still behaving as itself
  • 15Datadata access terms

What these numbers do not show

  • None of them were measured by a third party.
  • There is no head to head comparison with another agent authorization system, so none of this says APS is faster than anything else.
  • The layer measurements come from the Rust reference verifier, while the public harness measures the TypeScript SDK. They are different code paths and different numbers.
  • The runs against outside tests were made by me. The tests came from the other projects, and Toshi also wrote the adapter I checked.

What APS is

AI agents act for people and companies, but the systems around them often cannot show who authorized an action, what the agent was allowed to do, and what actually happened.

The Agent Passport System is an Apache 2.0 open protocol that gives an agent a verifiable identity, ties it to the person or company it represents, and checks the scope, budget and conditions of its authority before it acts.

Every permitted action gets a signed receipt, and every denied action leaves evidence.

Each receipt also records who the agent acted for, so the work, value and outcomes it produces stay attributed to the person or company behind it.
