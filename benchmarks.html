How long each check takes

AMD EPYC 7313P, one thread

Checking an action against authority already loaded into memory is faster than receiving a request over HTTP or waiting for an audit record to reach disk. The measurements below show those costs separately.

These are recorded results from the Runtime Passport prototype on an AMD EPYC 7313P running Ubuntu 22.04. Each benchmark runs sequentially on one thread. They describe the measured prototype revision, not the current TypeScript SDK or a production deployment.

median p99, on a logarithmic scale

The Rust measurement starts with prepared authority and action inputs. It does not include loading a passport, verifying its signature or fetching revocation information. The queued record measurement returns before the background writer completes the disk commit. The blocking measurement waits for that commit.

The HTTP measurement includes the local request and response, a recorded policy evaluation and creation of an evaluation receipt. It excludes a remote network trip and the business operation being authorized.

Read the result files and environment record. Each file identifies the measured code revision. Median is the middle recorded latency. p99 is the latency at the 99th percentile.

Inspect and reproduce

The performance records identify the code revisions, hardware, workloads and sampling methods behind the measurements. The Rust runner measures the local check. Separate TypeScript runners measure the native binding, audit modes and HTTP request.

For additional fixtures and implementation reports, see the Agent Authority Conformance lab. Read each record's scope and provenance before treating it as independent evidence.

These results describe specific implementations and test conditions. They do not establish production capacity or an independent security audit. An authorization receipt records a decision. Evidence from the protected resource is needed to establish whether the authorized operation completed.

What APS is

AI agents act for people and companies, but the systems around them often cannot show who authorized an action and what the agent was allowed to do.

The Agent Passport System is an Apache 2.0 open protocol that gives an agent a verifiable identity, ties it to the person or company it acts for, and checks the scope, budget and conditions of its authority before it acts.

Every action that goes through the gateway gets a signed decision, whether it is permitted or denied.

A receipt shows what was decided and under whose permission. It does not by itself show that the action succeeded outside the gateway.
