Content

Governance for publishers and data providers whose content is read, embedded, and trained on by AI agents.

Who this is for

News publishers, knowledge bases, scientific journals, data marketplaces, enterprise documentation owners. Anyone whose content is consumed by AI agents and who needs terms enforcement, attribution, and the ability to revoke.

robots.txt is advisory. It cannot enforce, cannot audit, cannot revoke. When an agent ingests your archive and an embedding lands in a derivative system three steps removed, you have no signed evidence of who took what and no way to pull it back.

What we ship

Governance blocks

Ed25519-signed JSON-LD embedded in your HTML. Declares terms (inference, training, redistribution, caching), revocation policy, and content hash. Any agent that reads the page sees the signed terms.

aps.txt

Signed file at /.well-known/aps.txt. Site-wide governance with optional path overrides. Like robots.txt, but cryptographically signed and bound to a revocation endpoint.

Source receipts

Publisher-issued receipt declaring "this is content I authored under these terms." Agents bind their access to a SourceReceipt, creating the cryptographic anchor for everything downstream.

Access receipts

Agent-signed proof of "I read this content under these terms at this time for this stated purpose." Carries the source DID, the terms version, and the intended usage.

Derivation receipts

Multi-hop lineage. RAG chunks, embeddings, summaries, model weights, synthetic derivatives all chain back to source via signed derivation receipts. Cycle detection and break markers for external boundaries.

Decision lineage receipts

For decisions made on top of your content (loan approval, content moderation, risk assessment), the decision artifact carries a signed list of contributing sources. Right-to-explanation primitive.

How revocation works

A publisher revokes one source. The cascade propagates through every receipt that depends on it. Downstream consumers see their bundles taint and can choose how to respond.

1
Publisher updates aps.txt revocation endpoint, marks source did:web:example.com#article-42 as revoked.
2
Every AccessReceipt citing that source is now flagged. Verifier checks the revocation endpoint; receipts emitted before revocation remain valid for compliance, but new access fails.
3
DerivationReceipt chains rooted at the revoked source carry the revocation signal. Embeddings, summaries, RAG chunks all surface the taint to downstream consumers.
4
DecisionLineageReceipt on top of derivatives flags decisions that depended on revoked sources. Audit can replay and quantify impact.

How it looks in code

Publisher side: sign a governance block and embed it in the page. The full pipeline (parse, verify, access receipt, terms enforcement) runs in one call on the consumer side.

// CONSUMER SIDE
// One call covers the full Governance 360 loop:
// extract block from HTML, verify signature + content hash,
// check terms against intended usage, sign access receipt.

import { governance360 } from 'agent-passport-system'

const result = await governance360({
  html: pageHtml,
  contentBody: articleText,
  sourceUrl: 'https://example.com/article-42',
  publisherPublicKey: publisherPubKeyHex,
  intendedUsage: 'inference',         // or 'training', 'redistribution', etc.
  agentPrivateKey: agentPrivKeyHex,
  agentPublicKey: agentPubKeyHex,
})

if (!result.allowed) {
  // result.reason: 'usage_not_permitted' | 'signature_invalid' | 'content_hash_mismatch' | 'revoked'
  return result
}

// result.accessReceipt: signed proof the agent read the content under the terms.
// Bind it to whatever you produce; downstream verifiers can check the chain.
return result.accessReceipt

What access receipts do not prove

A signed AccessReceipt proves an agent fetched content from a source under stated terms at a stated time for a stated purpose. It does not prove:

  • The agent obeyed the declared purpose downstream (signed intent, not enforcement of intent)
  • The content was authored by whom the source claims (signed by the publisher's key, not an external authority)
  • Compensation was paid (separate receipt class, separate ceremony)
  • The terms are legally enforceable in your jurisdiction
