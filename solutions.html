4 categories One protocol stack

Solutions

One protocol stack, four buyer paths. Pick the one that fits the problem you're trying to solve.

AEOESS ships an open protocol for AI agent identity, scoped delegation, governance, attribution, and commerce. The same primitives underpin every category below; each page tells you which subset matters for your problem and how it lands in code.

Not sure which one? Read the Who this is for section on each page. If your problem maps to two categories, both are accurate and both ship from the same SDK; the divergence is in framing, not in primitives.

For fintech, marketplaces, B2B

Payments

Companies whose agents move money. Refunds, charges, procurement, settlement.

Six payment rails (Foundation, AP2, x402, Stripe Issuing, ACP, MPP). 4-gate spending controls. Two-tier denial vocabulary. Reserve attestations. Conformance harness.

Read the page →
For regulated industries, EU operators, CCOs

Compliance

Companies that need to hand a regulator a cryptographic audit trail, not log lines.

Action receipts, contestability lifecycle, instruction provenance, APSBundle Merkle aggregation, claim-evidence type registry, framework mapping for EU AI Act, NIST AI RMF, ISO 42001.

Read the page →
For publishers, data providers, IP owners

Content

Publishers whose content is read, embedded, and trained on by AI agents.

Signed governance blocks, aps.txt at the well-known endpoint, source receipts, access receipts, derivation lineage with cycle detection, revocation cascade across derivatives.

Read the page →
For companies running internal agent fleets

Enterprise

Teams running agents across engineering, ops, legal, finance, sales. Need identity, scoped delegation, mutual auth, charter governance, gateway enforcement.

Bring your own identity (did:key, did:web, SPIFFE, OAuth, did:aps). Cascade revocation. Earned reputation. Posture overlay. Human escalation flags. Policy eval under 2ms.

Read the page →
One stack, four lenses. A publisher with EU operations needs Content + Compliance. A fintech with internal agents needs Payments + Enterprise. The pages cross-link in their Adjacent solutions sections so you can map your real situation onto the categories. The protocol primitives compose; the page boundaries are for finding the right entry point. Read the spec for the full primitive list.
