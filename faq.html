Faq

Frequently asked questions.

Common questions about the Agent Passport System.

01What does the protocol do?+
Agent Passport System checks an AI agent's delegated authority before it acts and records each decision. Every agent gets a cryptographic identity (Ed25519). Scope can only narrow, never expand. Trust is earned through performance. Revoking one delegation revokes everything delegated beneath it.
02How is it different from agent frameworks?+
Most frameworks handle orchestration. Agent Passport System handles enforcement: what can this agent do, and what happens when it violates a constraint? Bring your own identity. The gateway is both judge and executor. Works with any framework.
03Is this production-ready?+
APS ships versioned SDKs for TypeScript, Python, Rust and Go, an MCP server, conformance test vectors and an IETF Internet-Draft, all under Apache 2.0. Whether it is ready for your production use depends on your deployment. The threat model states what the protocol protects against and what it does not.
04How does delegation work?+
A human delegates authority to an agent with explicit scope: tools, money, services. The agent can sub-delegate, but scope can only narrow, never expand. Revoke the root and every delegation beneath it is revoked.
05Can an action bypass the gateway?+
Yes, if it has another path to the resource. The gateway checks and records only the requests that reach it. An agent that holds its own credentials for the resource can act without the gateway, and that action is neither checked nor recorded. Keeping resource credentials behind the gateway is part of the deployment. A signed receipt shows what the gateway decided. It does not show that every action went through the gateway or that an outside system completed the action. On the open source gateway a new tenant starts in observe mode, where a request outside the delegation is reported as a denial but comes back with an effective verdict of permit until the mode is set to enforce. The gateway documentation shows both modes.
06What happens if the gateway is unavailable?+
The evaluate route of the gateway returns a decision and calls no resource. Your calling code has to read effective_verdict and run the action only on a permit. When no usable decision arrives, the error handling in that calling code decides whether the action runs, and APS does not decide it. To keep enforcement during an outage, refuse to run an action that has no permit. Uptime of a gateway you host depends on how you run it, and this site makes no availability commitment for a hosted deployment.
07When does revocation take effect?+
At a gateway, once that gateway has the revocation and is set to enforce. A revoked delegation gives no authority to the delegations derived from it. On the open source gateway the revoke route marks that one delegation as revoked in its database, and the delegations beneath it lose authority when their chain is checked at the next evaluation. In observe mode that evaluation reports the denial without blocking, so blocking needs enforce mode and calling code that obeys the decision. The SDK has a separate signed revocation record. An action that ran before the revocation is not undone. How quickly a revocation reaches every gateway depends on how revocation state is distributed in your deployment. A verifier that works from a cached copy can accept a revoked delegation until the cache is refreshed, and short delegation lifetimes and frequent checks shorten that window. The threat model describes this limit.
08Who holds the signing keys?+
In a deployment you host, you do. The open source gateway generates its Ed25519 signing key on first start, stores the private key as plain hex in its own SQLite database and publishes the public key at /.well-known/jwks.json. The SDK has separate helpers for key storage, key rotation and remote signing, and they do not protect the signing key of the gateway on their own. Protecting the gateway database and choosing which keys a verifier trusts are the job of whoever runs the deployment.
09What identity systems are supported?+
Bring your own: did:key, did:web, SPIFFE SVID, OAuth. Cross-language: signatures round-trip TS ↔ Python byte-identically across 27 fixtures.
10Can I self-host?+
Yes. The gateway source is public under Apache 2.0 at agent-passport-system/agent-passport-gateway. It includes a Dockerfile and Terraform, Helm, Docker and air gapped variants for your own infrastructure, and you build it from source. You hold your keys, your records and your enforcement decisions. The gateway documentation lists which commands were run and which were not.
11Where is APS used or cited?+
Independent papers and Internet-Drafts that cite or reference APS are listed on the research page. Three contribution PRs were merged into Microsoft's Agent Governance Toolkit in March and April 2026, and their files were later removed upstream. The APS MCP server is listed in awesome-mcp-servers. A crosswalk to Edison Munoz Duran's Agent-DID identity layer lives in the agent governance vocabulary. None of these is an endorsement of APS.
12How do I contribute?+
Open an issue or a pull request on GitHub. The reference SDK is at agent-passport-system/agent-passport-system. Shared terms and crosswalks live in the Agent Governance Vocabulary. Conformance fixtures go to the conformance suite at the Agent Authority Conformance lab.
13Is it open source?+
Yes. Apache-2.0 licensed. The protocol, the SDKs, the MCP server and the gateway source are on GitHub. Nine research papers published on Zenodo. TypeScript SDK on npm, Python SDK on PyPI, Rust SDK on crates.io, Go SDK on pkg.go.dev.
14What is the Values Floor?+
Seven non-negotiable principles (F-001 through F-007): traceability, honest identity, scoped authority, revocability, auditability, non-deception, proportionality. Agents sign cryptographic attestations. Compliance is checked through graduated enforcement: inline (blocks execution), audit (logs violations), warn (advisory).
15What is V2 Constitutional Framework?+
A set of governance modules addressing what happens when compliant agents still cause systemic failures, designed through cross-model adversarial review. They cover approval fatigue detection, effect enforcement, semantic drift, governance drift tracking, emergence detection, separation of powers, constitutional amendment, circuit breakers and affected-party standing. Several of these moved out of the SDK. Their files in src/v2/ now throw an error that says the module moved to the gateway. Check a module in the source before you build on it.
16What is Data Lifecycle Governance?+
These modules record and check what happens to data after access: through transformation, across system boundaries, after consent revocation, into decisions, and under dispute. Key primitives: Extended Derivation Continuity (multi-hop chains with break markers and lineage confidence), Post-Revocation Obligations (a signed record that names the obligation for each artifact type, for example delete if cached for retrieved chunks, retraining required for model weights and ledger exempt for settlement records. The record names the obligation, and the system that holds the data has to carry it out), Decision Lineage Receipt (links a decision to the data sources recorded for it), Purpose Taxonomy (hierarchical with wildcard matching), Retention TTL (ephemeral vs persistent access), Terms Version Pinning (freezes terms at access time for settlement). Phase 2 adds aggregation controls, jurisdiction envelopes (jurisdiction metadata checked against transfer restrictions you configure), governance taint propagation, dispute state, combination constraints (checks against forbidden source IDs or classes you supply), access snapshots (anti-rug-pull), rights propagation semantics, purpose drift detection, and re-identification risk declarations. These helpers carry context and do not decide legal compliance.
17What is the Decision Lineage Receipt?+
The bridge between decision provenance (Module 37) and data provenance (Modules 38-42). When an agent makes a decision that affects a human (loan denied, content moderated, insurance claim rejected), the human should be able to ask: "what data influenced this decision?" The Decision Lineage Receipt is a signed record that links the decision to the data sources recorded for it, with derivation depth, transform path, terms version at access, lineage confidence and compensation status. It covers the sources the system recorded, so a source that was never recorded does not appear. The issuer states how complete the lineage is, and a receipt for a model trained elsewhere can say that the lineage is incomplete.
18What MCP tools are available?+
With the default profile the local MCP server lists 154 tools, and that count includes tools that only return a migration notice. Other profiles register fewer. The tools cover identity, delegation, values and policy, signed communication, coordination, commerce and reputation-gated authority. See the MCP server documentation.
19Which parts of the protocol are required vs optional?+
Core protocol: Agent identity (Ed25519), delegation chains, cascade revocation, Values Floor, policy engine, ProxyGateway enforcement. In draft -04 a Core requirement binds an implementation that claims the conformance class it applies to, so what you must implement depends on the classes you claim. The status page lists them.

Extended modules (pick what you need): Coordination, commerce, DID/VC, E2E encrypted messaging, task routing, reputation-gated authority, governance provenance, and the v2 governance modules.

Ecosystem services such as agent matching and professional networking can be built on top of these primitives, but are not part of the open protocol and not required for any core functionality.
20How do I get started?+
Start with the Quickstart. It builds one governed action on your machine with a grant, a revocation and receipts, and its test asserts every outcome shown on the page. The Install page gives the install command and the current version for the TypeScript, Python, Rust and Go SDKs and for the MCP server. It also says what each SDK can issue and verify, because the four SDKs do different jobs. The hosted MCP endpoint is restricted for now, so use the local server.
21How does GDPR work with an append-only receipt chain?+
In the in-memory storage backend of the SDK, tombstoneReceipt() marks a receipt as tombstoned with a reason and replaces its action and result with reduced objects whose type, target and summary read [REDACTED]. The storage interface describes the intent as redacting the payload while keeping the hash chain and the signature. Other storage backends have to be checked separately. Redaction does not reach copies, backups or logs held elsewhere. Whether this satisfies an erasure request under GDPR is a legal question for your deployment, and APS does not answer it.

What APS is

AI agents act for people and companies, but the systems around them often cannot show who authorized an action and what the agent was allowed to do.

The Agent Passport System is an Apache 2.0 open protocol that gives an agent a verifiable identity, ties it to the person or company it acts for, and checks the scope, budget and conditions of its authority before it acts.

Every action that goes through the gateway gets a signed decision, whether it is permitted or denied.

A receipt shows what was decided and under whose permission. It does not by itself show that the action succeeded outside the gateway.
