FAQ

Frequently asked questions

Short answers about what APS does, how authority and revocation work, what the gateway enforces and how to run it yourself.

Getting started

01What does APS do?+
APS records which agent is acting, who authorized it and what it may do. A gateway can check that authority before an action and sign its decision.
02Do I need to replace my agent framework?+
No. A framework runs the agent. APS adds signed authority records and tools to check them. Enforcement depends on how you connect the gateway to the resources your agents use.
03Do I have to use APS identities?+
No. The delegation record takes any identifier scheme, and the verifier gets keys through a resolver you supply. SDK 8.0.1 has helpers for did:key and did:web, and helpers that carry a SPIFFE identity or an OAuth token you already verified. If an agent has no identity, the SDK can create a passport for it. The identity reference has the details.
04Which parts are required?+
The current wire format defines signed records for delegation, revocation and receipts. Your conformance claim names the roles your implementation performs, such as issuing authority or verifying receipts. Draft -04 requires the Core requirements that apply to those roles. The SDK modules for coordination, commerce, reputation and governance are optional. The status page lists the roles.
05Where do I start?+
Run the quickstart. It builds one governed action on your machine with a grant, a revocation and receipts, and its test asserts every outcome.

Authority

06Can an agent give another agent permission?+
Yes. An agent can pass on part of its authority and cannot give more than it received. The verifier checks the whole chain and its limits.
07When does revocation take effect?+
At a gateway, once that gateway has the revocation and is set to enforce. A revoked delegation gives no authority to the delegations derived from it. An action that ran before the revocation is not undone. A verifier that works from a cached copy can accept a revoked delegation until the cache is refreshed, so short delegation lifetimes and frequent checks shorten that window.

Security

08Can an agent bypass the gateway?+
Yes, if it has another path to the resource. The gateway checks and records only the requests that reach it. Keeping the resource credentials behind the gateway is part of the deployment.
09Does the gateway block actions by default?+
No. On the open source gateway a new tenant starts in observe mode. A request outside the delegation is reported as a denial and still comes back with an effective verdict of permit. Blocking needs enforce mode and calling code that obeys the decision. The gateway documentation shows both modes.
10What happens if the gateway is unavailable?+
The calling code decides. The evaluate route returns a decision and calls no resource, so your code has to read effective_verdict and run the action only on a permit. To keep enforcement during an outage, refuse to run an action that has no permit.
11Does a valid receipt show that an action succeeded?+
No. It shows that the record was not changed and what its signer reported. Evidence that the action happened comes from the system that carried it out.
12Who holds the signing keys?+
In a deployment you host, you do. The open source gateway generates its Ed25519 signing key on first start, stores the private key as plain hex in its own SQLite database and publishes the public key at /.well-known/jwks.json. Protecting that database and choosing which keys a verifier trusts are the job of whoever runs the deployment.

Deployment

13Is APS production ready?+
APS ships versioned SDKs for TypeScript, Python, Rust and Go, an MCP server and conformance test vectors under Apache 2.0. The protocol is also described in an individual IETF Internet-Draft. Whether it is ready for your production use depends on your deployment, and individual features differ in maturity. The threat model states what APS protects against and what it does not.
14Is APS an IETF standard?+
No. APS is described in an individual Internet-Draft. Publishing an Internet-Draft is not endorsement or approval by the IETF.
15Can I self-host?+
Yes. The gateway source is public under Apache 2.0 at agent-passport-system/agent-passport-gateway, and you build it from source. You hold your keys, your records and your enforcement decisions. The gateway documentation lists which commands were run and which were not.
16How does GDPR work with an append-only receipt chain?+
In the in-memory storage backend of the SDK, tombstoneReceipt() marks a receipt as tombstoned with a reason and replaces its action and result with reduced objects whose type, target and summary read [REDACTED]. The storage interface describes the intent as redacting the payload while keeping the hash chain and the signature. Other storage backends have to be checked separately. Redaction does not reach copies, backups or logs held elsewhere. Whether this satisfies an erasure request under GDPR is a legal question for your deployment, and APS does not answer it.

Project

17Where is APS used or cited?+
Independent papers and Internet-Drafts that cite or reference APS are listed on the research page. Three contribution PRs were merged into Microsoft's Agent Governance Toolkit in March and April 2026, and their files were later removed upstream. The APS MCP server is listed in awesome-mcp-servers. A crosswalk to Edison Munoz Duran's Agent-DID identity layer lives in the agent governance vocabulary. None of these is an endorsement of APS.
18How do I contribute?+
Open an issue or a pull request on GitHub. The reference SDK is at agent-passport-system/agent-passport-system. Shared terms and crosswalks live in the Agent Governance Vocabulary. Conformance fixtures go to the conformance suite at the Agent Authority Conformance lab.
19Is it open source?+
Yes. The protocol, the SDKs, the MCP server and the gateway source are on GitHub under Apache 2.0.

What APS is

AI agents act for people and companies, but the systems around them often cannot show who authorized an action and what the agent was allowed to do.

The Agent Passport System is an Apache 2.0 open protocol that gives an agent a verifiable identity, ties it to the person or company it acts for, and checks the scope, budget and conditions of its authority before it acts.

Every action that goes through the gateway gets a signed decision, whether it is permitted or denied.

A receipt shows what was decided and under whose permission. It does not by itself show that the action succeeded outside the gateway.
